## 1. 운영 원칙 (운영자가 정한 것 — 꼭 지키기)

**가격**
1. 실제 공식 가격만 씁니다. 식당·운영사·관광지·지자체·관광청 공식 홈페이지, 공식 PDF, 공식 SNS 메뉴판, 국내는 네이버·카카오 플레이스의 **업주 등록 메뉴판**.
2. 식당이 **자기 도메인에서 운영하는 주문 화면** 가격은 사용 가능. 배달 전용가·온라인 할인가라고 적혀 있으면 `조건부`로 넣습니다.
3. 금지: 제3자 배달앱(배민·Grab·foodpanda·Wolt·Uber Eats 등), 예약 사이트(Klook·KKday·Trip.com 등), 블로그·뉴스·리뷰, Numbeo 같은 평균 사이트, AI가 추정한 값.
4. 금액·원문을 그대로 씁니다. 환산·반올림·추정은 하지 않습니다. 가짜 값이나 추정값으로 빈칸을 채우지 않습니다.
5. 결과가 현실적이어야 합니다. "최소 비용 계산기"가 아니라, 보통 여행자가 실제로 쓰는 금액이 나와야 합니다.

**안내 글(가이드·팁·여행 시기)**
6. 근거 우선순위: 공식(관광청·운영사·정부) → 공신력 있는 언론 → 여행자 후기·블로그(설명 문장에 한해 허용, URL 필수). **안내 글에는 금액을 쓰지 않습니다.**
7. 틀린 부분만 고칩니다. 정보를 빼서 밋밋하게 만들지 마세요(「5~9월」을 「따뜻한 계절」로 흐리게 바꾸는 식은 피하기).

**사이트**
8. 광고·예약·제휴 링크·로그인·결제를 넣지 않습니다(애드센스 승인 후 광고 자리만 운영자가 결정).
9. 원본 엑셀(`data/source/`)은 고치지 않습니다. 고칠 일은 `data/additions/`, `data/overlays/`, `src/data/`에서만 합니다.

- 정적 HTML은 `scripts/guide-pages.ts`가 만들고, `vite.config.ts`가 빌드 때 `dist/`에 씁니다(한국어는 루트, 영어·일본어는 `dist/_l/en|ja/`).
- Worker(`worker/page.ts`)는 `?lang=en|ja`일 때 `_l/` 파일을 골라 보냅니다. `/_l/` 직접 접근은 404이고, `.html` 주소는 확장자 없는 주소로 301 이동합니다.
- **새 페이지를 추가할 때 고칠 곳**(한 곳이라도 빠지면 404나 색인 누락이 납니다):
  `src/ui/pages.ts`(PageId·경로) → `src/ui/App.tsx`(화면) → `src/ui/meta.ts`(제목·설명) → `src/i18n/ko|en|ja.ts` → `scripts/guide-pages.ts`(정적 HTML) → `vite.config.ts`(emit·사이트맵·RSS) → `worker/page.ts`(PAGE_PATHS) → `wrangler.jsonc`(`run_worker_first`) → 테스트(`tests/unit/url-state.test.ts`, `tests/e2e/calculator.spec.ts`).
- 사이트맵 `https://howmuchthere.com/sitemap.xml`, RSS `https://howmuchthere.com/rss.xml`(네이버 서치어드바이저 제출용), `robots.txt`, `ads.txt`는 빌드 때 자동으로 만들어집니다.

### 도시 가이드 한 페이지의 구성(위에서 아래로)
제목 → 소개(`city-intros`) → 추천 기간 → 계산기 버튼 → 목차 → **언제 가면 좋을까**(`city-when` + 날씨 `city-seasons` + 해당 도시 시즌 행사) → 놓치지 말 것(`city-guides` h) → 숙소 동네(`city-intros` s) → 교통 이용권 → 먹어 볼 음식(`foods`) → 팁과 조심할 점(`city-guides` t + 나라 `country-guides`) → 입장료·현지 비용 → 계산기 버튼.
볼거리·팁·여행 시기의 근거 URL은 검수용 데이터로 유지하며, 가이드 본문에는 별도의 「근거」 링크를 표시하지 않습니다.

## 4. 가격 CSV (22열)

```
"ID","국가","도시","카테고리","세부유형","항목(한글)","Item (English)","최소","최대","통화","단위","가격형태","대상","출처등급","모델사용","상태","조회일","적용/게시","출처명","출처 URL","원문 인용","비고"
```
- **ID**: 도시 영문 3글자 + 종류 + 번호(`FD` 식사, `SN` 간식·음료, `AL` 주류, `TR` 시내 교통, `AP` 공항 이동, `AT` 관광). 기존 ID와 겹치면 변환이 멈춥니다.
- **국가·도시**: `cities-expansion-*.csv`의 한글 표기와 똑같이.
- **카테고리**는 4개뿐: `외식` / `교통` / `공항이동` / `관광`.
  다른 AI가 `식사`·`간식`·`주류`·`관광지`·`공항`으로 보내면 바꿔서 넣습니다:
  `식사`→`외식`(세부유형 `저가 한끼`/`중가 한끼` 그대로), `간식`→`외식`(세부유형 `간식`), `주류`→`외식`(세부유형 `주류`), `관광지`→`관광`, `공항`→`공항이동`.
- **식사 세부유형**은 `저가 한끼`/`중가 한끼`(**"한끼" 붙여 쓰기**).
- **교통**: 1회권은 세부유형에 공백 뒤 "1회"가 있어야 인식됩니다(`버스 1회권`, `시내 1회권`). 1일권은 `무제한권`으로 바꿉니다.
- **최대**를 비우면 "시작가"로 표시됩니다. 최소만 있는 고정가는 최대에 같은 값을 넣으세요.
- **공항 이동은 1인 요금만** 넣습니다(계산기가 인원수만큼 곱함). 택시 정액(차량 1대 요금)은 `exclusions.json`으로 빼거나 넣지 않습니다.
- 출처등급 `A 공식`, 모델사용 `예`(애매하면 `조건부`), 상태 `확정 1차`.

## 5. 새 도시 공개 체크리스트

1. `data/additions/cities-expansion-<n>-<날짜>.csv`에 등록(처음엔 `2차`=숨김).
2. 가격:
   - 같은 나라 도시가 이미 있으면 **교통 1회권 1건 이상 + 관광지 3곳**이면 됩니다(식사는 같은 나라 가격을 빌려 씀). 그래도 식당 2곳은 넣는 편이 좋습니다.
   - **새 나라**면 식당 3곳(식사), 교통, 관광지 3곳 + `country-guides`에 그 나라 tips·cautions(근거 URL 포함)가 필요합니다.
3. 대표 음식: `foods-<id>.csv`, `food-info.json`(ko/en/ja), `food-reasons-en.json`. 출처 URL 필수(없는 음식은 넣지 않음).
4. 안내 글: `city-intros`, `city-seasons`(URL), `city-when`, `city-guides`(h 3~4개, t 2개) + 근거 키(`city-guide-sources.ts`, `city-when-sources.ts`).
5. 일본어 이름(`places.ts`), 새 나라면 `COUNTRY_EN`.
6. `조사 단계`를 `파일럿`, 상태를 `공개(날짜)`로 바꿉니다.
7. `npm run data:convert` → `npm run status:update` → `npm run verify`.
8. 공개 후 `npx tsx scripts/check-data.ts`로 금액이 현실적인지 봅니다(같은 나라 다른 도시와 비교: `npm run data:compare`).

## 6. 다른 AI(크롬 등) 결과를 반영하는 방법 — 스크립트

결과 원본은 항상 `GPT전달내용/결과/`(또는 `Claude크롬전달내용/결과/`)에 두고, 정리본만 `data/additions/`에 넣습니다.

| 결과 파일 이름 | 명령 | 하는 일 |
| --- | --- | --- |
| `음식출처_*.csv` (키, 판정(확인/확인불가), 출처명, 출처URL, 확인일) | `npm run import:food-sources` | `확인`만 `food-sources.json`에 합침 |
| `음식사진_*.csv` (키, 도시, 음식(한글), Food, 사진 URL, 작가, 라이선스, 파일 페이지, 메모) | `npm run import:food-photos` | 위키미디어 **원본 주소**(md5 경로 확인)·자유 라이선스(CC0·PD·CC BY·CC BY-SA)·작가가 있는 것만 960px 썸네일로 저장. 이미 사진이 있으면 건드리지 않음 |
| `근거보강_*.csv` (키, 판정(확인/수정/삭제), 수정_ko·en·ja, 근거URL, 근거종류, 메모) | `npm run import:guide-sources` | 확인·수정 줄의 근거 URL을 근거 파일에 합침 |
| 같은 파일 | `npm run apply:guide-fixes` | `수정` 줄의 문장을 데이터 파일에 반영. 반영 못 한 줄은 「직접 확인」으로 출력 → 손으로 고침 |

- `apply:guide-fixes` 주의: 시기·이름이 바뀌었는데 영어·일본어가 「이름 — 설명」 형식이 아니면, 스크립트 안의 `LABELS`에 세 언어 이름을 직접 적어야 합니다. 시기를 흐리게만 바꾼 줄은 `KEEP_LABEL`에 넣어 원래 시기를 유지합니다.
- 먼저 `npx tsx scripts/apply-guide-fixes.ts --dry`로 확인하세요.
- 반영 후에는 항상 `npm run data:convert` → `npm run verify`.
