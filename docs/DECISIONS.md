# 주요 결정 기록

구현 중 결과에 영향을 주는 판단을 기록한다. 바꿀 때는 이 문서와 테스트를 함께 고친다.

## 계산 규칙

| 결정 | 내용 | 이유 | 위치 |
| --- | --- | --- | --- |
| 최소 표본 3건 | 필수 바스켓마다 **독립 표본 3건 이상**일 때만 금액을 낸다 | 소수 표본으로 단정적 금액을 만들지 않기 위해(요청 사항) | `MODEL.minSamplesPerCategory` |
| 독립 표본 | 같은 출처·같은 상품의 용량·기간·요일 변형(24/48/72시간권, 4/8개입, 평일/주말)과 성인·아동 가격은 1건 | 변형으로 표본 수가 부풀지 않게 | `productKey`, 성인/아동 풀 분리 |
| 유형별 바스켓 | 1일 이용권·1회권·식사·간식·입장권·기념품을 따로 계산 | 단위가 다른 가격을 한 분포로 섞지 않기 위해 | `BASKET_RULES` |
| 교통 대체 관계 | 1일권과 1회권은 더하지 않고, 둘 다 계산 가능하면 두 범위를 합친 하나의 선택 범위 | 여행자는 둘 중 하나를 쓴다 | `mode: 'alternatives'` |
| 관광 탑승 분리 | 케이블카·곤돌라는 1회권이 아니라 관광 입장권 | 일상 이동 요금이 아님 | `KEYWORDS.sightseeingRide` |
| 같은 명소 옵션 1건 | 관광지는 같은 출처·같은 명소의 관람 옵션(계단/엘리베이터/정상 등)을 1건 | 한 명소의 옵션이 서로 다른 관광지처럼 세어지는 것을 막음 | `venueKey` |
| 일일 상한 | 공식 하루 상한(TfL daily cap)이 있으면 **같은 대중교통 요금 체계의** 1회권 하루 비용만 자름. 공유자전거·킥보드·수상교통 등 별도 체계(예: `LON-TR-005` Santander Cycles)는 자르지 않고 따로 계산한 뒤 두 범위를 합침 | 상한은 버스·지하철에만 적용되는 공식 규칙(검수 지적 1) | `KEYWORDS.dailyCap`, `KEYWORDS.capExempt` |
| 제외 | 택시·전용차·차량 단위·왕복/구간 셔틀·사이드 메뉴·D등급·보류·모델 사용 아니오·거주자 전용 요금·"○○ 미만" 상한 문구 | 방문객 1인 가격이 아니거나 근거 부족 | `classify()` |
| 방문일 반영 | 평일/주말 변형·판매 기간만 날짜로 반영. 날짜에 유효한 독립 표본이 3건 미만이면 부족 | 근거 없는 성수기 배수 금지 | `poolOnDate`, `priceBasket` |
| 개선문 월·요일 규칙 | `PAR-AT-006`(4~9월 €22·수요일 €16, 10~3월 €16)은 비고의 자유 문장이라 날짜별로 자동 적용하지 않음. 방문일과 무관하게 €16–22 범위 + "선택한 방문일의 확정 요금이 아님" 경고 | 단일 가격으로 오인하지 않게(검수 지적 2) | `isVariablePricing` |
| 변동 가격 | 수요형·일정형, 그리고 변형 없이 범위만 있는 `요일/기간형`(예: 개선문 €16–22)은 범위 유지 + 경고(범위 함께 표시) | 비고의 자유 문장을 날짜 규칙으로 자동 해석하면 데이터가 바뀔 때 틀리기 쉬움 | `isVariablePricing` |
| 관광지 직접 선택 | 갈 곳을 고르면 관광 비용을 평균 추정 대신 고른 곳의 입장료 합계(1곳 1회)로 계산. 아동 요금은 같은 상품의 아동 표본, 없으면 성인 요금(경고). 3건 기준은 적용하지 않음 | 사용자가 정한 실제 방문지의 공식 가격이므로 분포 추정이 필요 없음 | `selectedAttractions`, `attractionOptions` |
| 현지 물가 표 | 바스켓별 중앙값·범위를 계산과 같은 표본 선택 규칙으로 표시. 독립 3건 미만은 "참고용" | 별도 수치를 만들지 않기 위해 | `priceGuide` |
| 항목별 예비비 | 예비비 10%를 항목(외식·교통·관광·기념품)마다 따로 표시. 합은 전체 예비비와 같음 | 어느 항목에 얼마의 여유를 두는지 보이게 | `CategoryEstimate.contingency` |
| 음주(선택) | "음주 포함"을 고르면 외식에 주류 바스켓(성인만, 하루 1/2/3잔, 첫날·마지막 날 60%)을 더함. 주류 표본이 3건 미만이면 금액을 만들지 않고 안내 | 가격을 지어내지 않음. 현재 주류 표본 0건 | `BASKET_RULES.food`, `drinkNoData` |
| 자세히 보기 | 일차별 내역(`DetailLine`)은 계산과 같은 값에서 나오며 일차 합 = 항목 합계(테스트) | 화면 숫자와 계산이 어긋나지 않게 | `priceBasket` |
| 세금 별도 | `450++` 등은 값을 바꾸지 않고 경고 | 가격을 임의로 보정하지 않음 | `KEYWORDS.taxExcluded` |
| 스타일 | 같은 바스켓에서 읽는 분위 구간(0–50/25–75/50–100%)과 이용 횟수만 바꿈 | 가격을 새로 만들지 않음 | `MODEL.styleBand`, `MODEL.usage` |

## 데이터

- 원본 엑셀은 수정하지 않고 버전별 파일로 보존, `data/source/latest.json` 이 최신을 가리킨다.
- 변환 결과와 도시 판정(`status.json`), 조사 요청 목록(`data/research-queue.md`)은 변환 때 자동 생성되고 CI 가 동기화 여부를 검사한다.
- 엑셀의 요약 시트(`도시 초안`·`다음 조사 큐`)는 읽지 않는다. 작성 시점이 달라 오래된 수치(예: 다낭 기념품 0건)가 있어, 화면·방법론·조사 요청 목록의 수치는 모두 가격 원장과 계산 코드로 다시 만든다(검수 지적 3).
- 원문 가격을 재확인하지 못한 표본은 `data/overlays/review-flags.json` 에 검수 메모로 남긴다. 가격·분류는 바꾸지 않고 결과의 재검증 경고·방법론 "재검증 필요 표본"·조사 요청 목록에 표시한다. 현재: `DAD-AT-004` 다낭 참조각박물관 60,000 VND(원문 미확인, 검수 지적 4).
- 영어 음식 추천 이유는 엑셀에 없어 `data/overlays/food-reasons-en.json` 에 별도 번역으로 둔다(가격 아님).
- e2e 는 배포와 같은 실제 데이터만 쓴다. 테스트 전용 가짜 가격은 없다.

## 화면·광고

- 본문 760px, 전체 1160px 이내. 1200px 이상에서만 좌우 160px 광고 레일(160+20+760+20+160 = 1120px).
- 1200px 미만은 레일을 숨기고 결과 뒤 인라인 자리 1개만(모바일 320×50, 태블릿 728×90 표준 크기). 이전 버전의 250px 칸 3개는 없앴다.
- 광고 자리는 `placeholder`(표지만, 레일 160×120 고정)와 `filled`(`.ad-slot__content` 에 노드가 들어오면 자동 전환) 두 상태로 나눈다.
  표지 상태는 작게 유지해 큰 빈칸이 없고, 채워진 레일은 높이 자동·세로 잘림 없음·160px 초과 가로만 잘라 본문을 가리지 않는다.
  레일은 본문과 다른 grid 열이라 레일이 길어져도 본문 폭·위치가 바뀌지 않는다 — 테스트용 가짜 160×600 콘텐츠로 검사(실제 광고 아님).
  실제 광고 코드·광고 단위 규격 연결과 실제 광고 렌더링 확인은 후속 작업이다.
- 인라인 자리는 채워져도 표준 높이(320×50 / 728×90)를 유지한다(CLS 방지). 다른 규격을 쓰려면 높이 예약값을 함께 바꿔야 한다.
- fixed·sticky·오버레이 광고, 실제 광고 코드·계정 ID·추적 스크립트는 넣지 않는다(테스트로 검사).
- 언어(한/영)와 표시 통화는 독립이며 URL 에 함께 보존된다.
- 결과는 숫자·내역 중심. 근거·출처·경고 패널은 기본 접힘(지우지는 않음 — 표본 수·출처·확인일·경고 표시는 요구 사항).

## 환율

- 서버(Worker)가 무료 API(ExchangeRate-API 오픈 → Frankfurter)를 호출해 24시간 캐시하고, 실패 시 마지막 정상값을 "오래된 값"으로 표시하며 값이 없으면 현지 통화만 보여준다.
- 이 개발 환경에서는 외부 API 접속이 막혀 실제 호출은 검증하지 못했다(모킹 테스트만).
