# 주요 결정 기록

구현 중 결과에 영향을 주는 판단을 기록한다. 바꿀 때는 이 문서와 테스트를 함께 고친다.

## 데이터

- 원본 엑셀은 수정하지 않고 버전별 파일로 보존, `data/source/latest.json` 이 최신을 가리킨다.
- 변환 결과와 도시 판정(`status.json`), 조사 요청 목록(`data/research-queue.md`)은 변환 때 자동 생성되고 CI 가 동기화 여부를 검사한다.
- 엑셀의 요약 시트(`도시 초안`·`다음 조사 큐`)는 읽지 않는다. 작성 시점이 달라 오래된 수치(예: 다낭 기념품 0건)가 있어, 화면·방법론·조사 요청 목록의 수치는 모두 가격 원장과 계산 코드로 다시 만든다(검수 지적 3).
- 원문 가격을 재확인하지 못한 표본은 `data/overlays/review-flags.json` 에 검수 메모로 남긴다. 가격·분류는 바꾸지 않고 결과의 재검증 경고·방법론 "재검증 필요 표본"·조사 요청 목록에 표시한다. 현재: `DAD-AT-004` 다낭 참조각박물관 60,000 VND(원문 미확인, 검수 지적 4).
- 영어 음식 추천 이유는 엑셀에 없어 `data/overlays/food-reasons-en.json` 에 별도 번역으로 둔다(가격 아님).
- e2e 는 배포와 같은 실제 데이터만 쓴다. 테스트 전용 가짜 가격은 없다.

## 화면·광고

- 본문 760px, 전체 1160px 이내. 1200px 이상에서만 좌우 160px 광고 레일(160+20+760+20+160 = 1120px).
- 1200px 미만은 레일을 숨기고 결과 뒤 인라인 자리 1개만(모바일 320×50, 태블릿 728×90 표준 크기). 이전 버전의 250px 칸 3개는 없앴다.
- 광고 자리는 `placeholder`(표지만, 레일 160×120 고정)와 `filled`(`.ad-slot__content` 에 노드가 들어오면 자동 전환) 두 상태로 나눈다.
  표지 상태는 작게 유지해 큰 빈칸이 없고, 채워진 레일은 높이 자동·세로 잘림 없음·160px 초과 가로만 잘라 본문을 가리지 않는다.
  레일은 본문과 다른 grid 열이라 레일이 길어져도 본문 폭·위치가 바뀌지 않는다 — 테스트용 가짜 160×600 콘텐츠로 검사(실제 광고 아님).
  실제 광고 코드·광고 단위 규격 연결과 실제 광고 렌더링 확인은 후속 작업이다.
- 인라인 자리는 채워져도 표준 높이(320×50 / 728×90)를 유지한다(CLS 방지). 다른 규격을 쓰려면 높이 예약값을 함께 바꿔야 한다.
- fixed·sticky·오버레이 광고, 실제 광고 코드·계정 ID·추적 스크립트는 넣지 않는다(테스트로 검사).
- 언어(한/영)와 표시 통화는 독립이며 URL 에 함께 보존된다.
- 결과는 숫자·내역 중심. 근거·출처·경고 패널은 기본 접힘(지우지는 않음 — 표본 수·출처·확인일·경고 표시는 요구 사항).

## 환율

- 서버(Worker)가 무료 API(ExchangeRate-API 오픈 → Frankfurter)를 호출해 24시간 캐시하고, 실패 시 마지막 정상값을 "오래된 값"으로 표시하며 값이 없으면 현지 통화만 보여준다.
- 이 개발 환경에서는 외부 API 접속이 막혀 실제 호출은 검증하지 못했다(모킹 테스트만).

## 방법론 페이지 제거, 소개·개인정보처리방침 추가 (2026-10-02)

- 방법론·출처 페이지는 운영자 판단으로 제거했다(증명용 계산 설명이 사용자에게 필요하지 않음). 출처·확인일·경고는 결과 화면에 남긴다.
- AdSense 심사용으로 `/about`, `/privacy` 를 추가했다. 문의처는 `VITE_CONTACT_EMAIL` 이 없으면 지어내지 않고 "준비 중"으로 표시한다.
- `ads.txt` 는 `ADSENSE_PUBLISHER_ID` 가 있을 때만, 형식 검사 후 생성한다.

## 확장 방향: 국가 위주, 도시는 볼거리·먹거리 (2026-10-11)

- 운영자 방침: 먼저 국가를 늘린다. 같은 나라 안에서는 식사·교통 등 기본 물가가 크게 다르지 않다.
- 도시를 추가하는 이유는 사실상 세 가지다: 관광지, 테마파크, 그 도시에서 먹어 볼 음식.
- 그래서 새 나라는 기본 물가(식사·교통·간식·주류)를 충분히 모으고, 같은 나라의 새 도시는 관광지·테마파크 입장료와 대표 음식 위주로 모은다.

## 네이버·카카오 플레이스 업주 등록 메뉴 = 실제 가격 (2026-10-12)

- 운영자 방침: 실제 가격으로 계산한다. 지도 플랫폼 장소 페이지의 메뉴 탭은 업주가 올린 실제 판매 가격이므로 B등급·계산 사용(`예`)으로 둔다.
- 재확인에서 `확인불가`(지점 특정 불가·용량 미표기 등)가 나온 행만 조건부로 낮춘다. 출처가 사라진 행은 지금처럼 `exclusions.json` 으로 뺀다.
- 배달앱·예약·리뷰 사이트(Grab·foodpanda·quandoo·트립어드바이저 등)는 그대로 C등급·조건부.
- 효과(2인·3박·보통): 서울 37만~67만 → 38만~59만 원, 부산 48만~83만 → 50만~60만 원, 제주 48만~67만 → 56만~67만 원.

## 세금·팁이 빠지는 도시의 외식 가산 (2026-10-13)

- 미국·캐나다는 메뉴 가격에 판매세·팁이 빠져 실제 결제액이 20~30% 높다. 실제 쓰는 금액에 맞추려고 `MENU_SURCHARGE`(model-config)로 식사·술에 세금 + 팁, 간식·음료에 세금만 더한다.
- 세금은 정부 공식 세율(뉴욕시 8.875%, 하와이 GET 4.5%, 캐나다 GST 5% + BC 주류 PST 10%), 팁은 계산 가정(뉴욕·호놀룰루 18~20%, 밴쿠버 15~18%).
- 가격 안내·출처에는 원래 메뉴 가격을 그대로 보여 주고, 결과에 "세금·팁 포함" 안내를 띄운다.
- 효과(2인·3박·보통): 뉴욕 970~1,147 → 1,194~1,411달러, 밴쿠버 1,084~1,135 → 1,261~1,328캐나다달러.

## 2026-10-14 한국·일본 도시는 더 늘리지 않는다
- 공개 66곳 중 한국 12곳·일본 11곳(35%)으로 쏠려 있다. 앞으로는 **새 나라와 그 밖의 나라 도시를 우선**한다.
- 이미 숨김 등록된 나라(일본)는 그대로 두되 조사 순서는 맨 뒤로 미룬다.

## 2026-10-15 식당 자체 사이트의 주문(장바구니) 화면 가격
- **식당·체인이 자기 도메인에서 직접 운영하는 메뉴·주문 화면의 가격은 써도 된다**(예: evos.uz, pkhalikhinkali.ge). 판매 주체가 직접 정한 가격이라 네이버·카카오 업주 등록 메뉴와 같은 취급.
- 단, 그 화면에 **배달 전용 가격·배달 수수료 포함·온라인 할인**이라고 적혀 있으면 `조건부`로 넣는다(매장 가격과 다를 수 있음). 표기가 없으면 `예`.
- 배민·Wolt·Glovo·Yandex Eats·Uber Eats·foodpanda 같은 **제3자 배달앱은 계속 금지**.
- 가격이 0이나 빈칸으로 보이는 화면(로그인·지점 선택 전)은 쓰지 않는다.

## 2026-10-16 도시 가이드 = 그 도시만의 안내 (경비 표 제외)
- 가이드에서 "3박 4일 예상 체류비"와 "현지 물가 한눈에"를 뺐다(계산기와 중복). 경비는 위·아래 "{도시} 여행 경비 계산해 보기" 버튼으로 계산기에서 본다(도시만 미리 선택, 일정은 사용자가 입력).
- 대신 **놓치지 말 것(볼거리 3곳 안팎)과 여행 팁(2~3개)** 을 넣는다. 데이터: `src/data/city-guides.ts`. 데이터가 없는 도시는 이 구역을 그리지 않는다.
- **안내 글의 출처 기준(가격과 다름)**: 관광청·운영사 공식 안내 + **실제 여행자 추천(블로그·커뮤니티 후기)도 허용**. 단 원문을 베끼지 않고 직접 요약하며, 근거 URL을 남긴다. 금액은 쓰지 않는다(금액은 가격 원장에서만).
- 가격은 지금처럼 공식 출처만.
